# User Story: Superpowers SDD Adapter

## Business Objective
Support `obra/superpowers` as a new SDD adapter for Architecture Guard. This allows projects using the Superpowers agentic workflow methodology to natively benefit from Architecture Guard's repository-specific structural governance, review checks, and drift detection.

## User Stories
- As an AI coding agent or developer using the Superpowers framework, I want to be able to run Architecture Guard natively within my workflow so that I get drift detection, validation, and architecture reviews without having to adopt a different SDD tool like SpecKit or OpenSpec.

## Acceptance Criteria
- Architecture Guard correctly detects a `superpowers` initialized repository using specific directory markers.
- Architecture Guard successfully maps its required artifacts (`spec`, `plan`, and `tasks`) to the corresponding planning and review artifacts generated by Superpowers.
- Architecture Guard enforces its structural rules on the Superpowers workflow artifacts.
- The new adapter is entirely contained within `adapters/superpowers.md` without duplicating core review/verification business logic.

## Business Rules
- **DRY Enforcement**: The adapter must act solely as a mapping layer. No core Architecture Guard evaluation logic or prompts may be duplicated into the adapter.
- **Ponytail Pragmatism**: Rely on Architecture Guard's existing native `adapters/` markdown mapping system.

## Out of Scope
- Writing a heavy, standalone plugin, executable, or external server integration for Superpowers. 

## Assumptions
- `superpowers` relies on standard markdown files for planning and skills that Architecture Guard can parse.
- We can definitively identify a `superpowers` repository via predictable directory markers (e.g., `.agent/skills/` or a config manifest).

## Risks
- Superpowers provides workflow discipline rather than a rigid SDD artifact schema, which might mean that its generated artifacts do not naturally map 1-to-1 with `spec`, `plan`, and `tasks`.

## Open Questions
- What is the exact file path or directory marker that definitively identifies a repository as using `superpowers`?
- Which specific artifact files does `superpowers` generate during its planning phase that we should map our `spec`, `plan`, and `tasks` to?
