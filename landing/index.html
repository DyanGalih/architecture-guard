The Flagship Skills

Two Commands That Change How You Build

Instead of memorizing a dozen manual steps, Architecture Guard centers on two primary high-level orchestrators: one for single features, and one for entire backlogs.

Hero Skill 01 · Single Feature Interactive Conductor

/ag-workflow

The all-in-one interactive conductor. Drives discovery, specification, planning, task generation, multi-agent implementation, and deep verification in one continuous, governed lifecycle with 4 structured human approval gates (Gates 0–3).

  • Single Entrypoint: No need to remember 6 separate phase commands
  • Human Control: Pauses at 4 mandatory gates for review and approval
  • Agent Teams: Coordinates parallel implementor roles and fresh review passes
/ag-workflow "Add real-time notifications with webhook fallback"
Hero Skill 02 · Sprint / Queue Autonomous Queue Engine

/ag-governed-backlog

The autonomous multi-item delivery queue. Reads stories, bugs, and tasks from Jira JQL, Beads (bd), or local backlog.yml, groups related items, executes them across Full/Fix/Light/Research lanes in isolated Git worktrees, and publishes 1 PR per group.

  • Batched Approvals: 4 batched gates (Queue, Specs, Scope, Pull Requests)
  • Isolated Git Worktrees: Work on your checkout is never disturbed
  • Resumable State: Tracks progress in .architecture-guard/queue.yml
/ag-governed-backlog

The Recommended Way to Use Architecture Guard

Choose the right flow based on your immediate engineering scope:

01

Single-Feature Delivery

Best for building or refactoring a specific feature. Use /ag-workflow to run the entire guided lifecycle in one continuous conversation.

# Start interactive delivery:
/ag-workflow "Feature Goal"
# Or granular:
/ag-governed-discover
/ag-governed-delivery
/ag-verify base=main
Recommended for daily feature work →
02

Sprint & Backlog Queues

Best for processing a prioritized queue of multiple bugs, tasks, and stories from Jira JQL, Beads (bd), or backlog.yml.

# Validate backlog format:
architecture-guard validate-backlog
# Run the backlog queue:
/ag-governed-backlog
# Batched Gates: Q, S, I, P
Recommended for sprint delivery →
03

PR Review & Feedback

Best for managing all team pull requests and handling incoming feedback on your own PRs across GitHub, GitLab, Bitbucket, and Azure DevOps.

# Scan & triage all open PRs:
/ag-pr-queue
# Or review specific PR:
/ag-review-pr 124
# Or address PR feedback:
/ag-pr-feedback
Recommended for code review ops →

Architecture Guard v3.7.0 Documentation

Specification-Driven Development, Multi-Agent Teams & PR Operations

1. Flagship Commands: /ag-workflow & /ag-governed-backlog

• /ag-workflow: Single-command interactive conductor for the full lifecycle (discovery → spec → plan → implement → verify → archive) with Gates 0–3.
• /ag-governed-backlog: Autonomous queue engine ingesting Jira JQL, Beads, or YAML across Full, Fix, Light, and Research lanes in isolated worktrees.

2. Multi-Agent Host Coordination

• Claude Code: Native Agent Teams (agteam-*) with peer messaging and quality gates.
• Antigravity (AGY): Native subagents API via invoke_subagent and share workspace isolation.
• OpenCode: Lead-coordinated native subagents with declarative read-only tool envelopes (tools: { write: false, edit: false, bash: false }).
• OpenAI Codex: Scoped child sessions via .codex/skills/ and feature reductions.

3. Deep Verification, Premise Grounding & 37 SonarLint Rules

Unlike standard linting, Architecture Guard verifies that planning artifacts cite true base-branch code (Premise Grounding), detects unlisted file readers/writers (Consumer Inventory), verifies artifact self-consistency, and enforces 37 architecture-focused SonarLint rules across Java, JavaScript, TypeScript, Python, and PHP alongside repository hygiene rules before code is pushed.

4. Backlog Queues, Per-Story Decomposition & Multi-Forge PR Automation

• /ag-governed-delivery-team: Decomposes features into parent and per-item child User Stories and syncs to Jira Epics/Stories or GitHub Issues.
• /ag-pr-queue: Manages pull request reviews and feedback triage across GitHub, GitLab, Bitbucket, and Azure DevOps in isolated worktrees with batched human gates.
